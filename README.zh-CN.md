# horus

<img src="docs/assets/horus-logo.png" alt="horus 标识" width="100%" />

[English](README.md) · [安装与使用](docs/usage.md)

**让编程助手成为你的测试工作台。**

horus 是一个 AI 原生接口测试平台。测试人员可以在已有的编程工具中，用自然语言完成
业务分析、测试设计、功能验证与基础并发测试，再根据结果判断业务是否符合预期。

- **轻量。** 复用编程助手已有的模型和工具，无需单独部署大型测试平台。
- **本地运行。** MCP 服务和测试引擎在本机运行，计划、执行记录和报告保存在本地。
- **通用接入。** 使用标准 MCP 协议，支持本地 MCP 的编程工具均可使用；
  Skill 可通过原生机制加载，也可让 Agent 直接读取。

导入接口文档，在线链接或本地文件均可。Agent 读取文档，梳理接口之间的业务调用关系，
结合你描述的业务风险和预期结果生成测试计划。你确认范围和检查标准后，
horus 执行测试、清理数据，交付有证据可查的结果。

```text
接口文档 + 业务目标 → 理解业务调用关系 → 测试计划 → 你确认 → 执行与清理 → 测试结果
```

## 功能

- **从接口文档梳理业务调用关系。** 识别接口及其调用依赖，结合需求和可选源码设计检查，
  说明测试依据、假设和未覆盖项。
- **验证完整业务流程。** 自动准备独立数据、传递接口返回值，检查权限、状态变化、条件分支
  和异步结果，最后清理。Hurl 同时核对返回数据和 HTTP 状态。
- **检查并发下的速度与正确性。** 按确认的并发数、迭代次数、时限和阈值运行 k6，检查延迟、
  请求错误、数据错误及完成次数。经授权后，可通过 SSH 补充机器资源观测。
- **看清测了什么、哪里有问题。** 报告按业务目标呈现结论、关键数据和 Mermaid 图，
  可继续查看失败检查及请求响应证据。未执行的路径、未解决的清理问题会明确列出。
- **保留并重跑每轮测试。** 已确认计划与结果放在同一目录，也可导出计划，通过 CLI 重跑，
  无需模型。中断后可单独尝试清理。

目前为 alpha 版本，运行环境为 macOS 或 Linux；被测服务的编程语言不限，
接口范围为 HTTP/REST + JSON。具体限制见
[架构说明](docs/architecture.md#current-limits)。

## 快速开始

把下面这段话发给你的编程助手：

```text
请按照 https://github.com/xucailiang/horus/blob/master/docs/usage.md 安装 horus，
在当前编程工具中配置 MCP 和 Skill，并验证连接。
```

Agent 会根据[接入指南](docs/usage.md)完成依赖安装、MCP 配置和 Skill 安装，手动步骤也在同一文档中。

Codex 和 Claude Code 已完成验证，其他 MCP 客户端使用同一套服务和流程。

配置完成后，在编程 Agent 中发起测试：

```text
用 horus 测试这个服务：<服务地址>，导入接口文档：<在线链接或本地文件路径>。
理解业务规则和接口调用依赖，设计功能测试与基础并发测试，包含数据准备和清理。
先直接在对话里给我看计划和负载范围，确认后再保存执行。
每轮计划和报告放在同一目录，用中文 Markdown 和 Mermaid 图展示业务逻辑与测试数据。
```

Agent 先在对话中展示计划，确认后才保存并执行。确认只适用于当前版本和范围；修改后需要重新审核。

## 测试报告

每轮测试的计划和结果放在同一目录，Markdown 文档的语言跟随当前对话：

| 文件 | 内容 |
| --- | --- |
| `plan.md` | 已确认的计划、业务规则和完整 Mermaid 调用图 |
| `report.md` | 结论、问题、业务结果、关键指标和业务简图 |
| `details.md` | 逐步检查与执行证据 |

同目录还保留可执行计划、完整的脱敏 JSON 结果和 JUnit 报告。
未执行的路径、尚未解决的清理问题会明确列出。
