# horus

<img src="docs/assets/horus-logo.png" alt="horus 标识" width="100%" />

[English](README.md) · [安装与使用](docs/usage.md)

**让你熟悉的编程工具，成为 AI 测试工作台。**

horus 是轻量的 AI 原生接口测试平台。导入接口文档，用自然语言描述你要验证的业务，就能在当前
编程工具里梳理业务调用关系、设计测试。你确认计划后，horus 完成功能验证、基础并发测试
和数据清理，再交付一份看得懂的报告。

你把精力放在业务规则、风险和通过标准上，编程助手帮你把这些判断变成具体测试，
整个过程在同一段对话中完成。

- **轻量。** 复用已有的编程助手和模型，无需再部署一套大型测试平台。
- **本地运行。** 从本机发起测试，计划、执行记录和报告保存在自己的工作区。
- **通用接入。** 支持本地 MCP 的编程工具均可使用，继续在你熟悉的环境里工作。

```text
导入文档 → 理解业务调用关系 → 确认计划 → 执行测试 → 清理与报告
```

## 功能

- **把接口文档变成业务测试计划。** 在线链接或本地文件均可。Agent 梳理接口之间的调用依赖，
  结合需求和可选源码，告诉你该测什么、为什么这样测，还有哪些问题需要确认。
- **把业务流程测完整。** 串联登录、创建数据、状态流转和异步结果，检查谁能访问或修改数据、
  返回值是否正确、业务规则是否成立。数据准备和清理一并纳入计划。
- **看并发时是否又快又正确。** 先确定并发数和负载范围，再检查多少请求完成、响应有多快、
  是否报错，以及返回的数据是否仍然正确。
- **拿到能帮助判断的结果。** 按业务目标呈现通过项、失败点和性能表现，用流程图说明测了什么，
  需要排查时再查看详细检查和请求响应记录。
- **每轮都能复盘和回归。** 计划与结果放在本轮独立目录，方便回看和排查。
  已确认计划可按原范围重跑，保留的记录便于对照。

目前为 alpha 版本，运行环境为 macOS 或 Linux；被测服务的编程语言不限，
接口范围为 HTTP/REST + JSON。具体限制见
[架构说明](docs/architecture.md#current-limits)。

## 快速开始

把下面这段话发给你的编程助手：

```text
请按照 https://github.com/xucailiang/horus/blob/master/docs/usage.md 安装 horus，
在当前编程工具中完成接入，并验证连接。
```

把安装和配置交给编程助手。手动安装及其他工具的接入方式见[使用指南](docs/usage.md)。
Codex 和 Claude Code 已完成验证，其他 MCP 客户端使用同一套测试流程。

然后给它接口文档和测试目标：

```text
用 horus 测试这个服务：<服务地址>，导入接口文档：<在线链接或本地文件路径>。
梳理业务调用关系，设计一轮功能测试和基础并发测试。
先把要验证的业务、通过标准和负载范围直接给我看，等我确认后再执行。
最后清理本轮数据，给我一份能看懂业务结果、失败原因和关键指标的报告。
```

计划直接在对话中展示，确认后才保存和执行。计划或负载有变化时，由你重新确认。

## 测试报告

先看一份简短报告：测了什么、哪些通过、哪里失败、性能如何、数据是否清理干净。
业务流程图把结果和原计划对应起来，未执行的检查、未解决的清理问题会明确说明。

每轮计划与结果放在同一目录，文档语言跟随当前对话：

| 文件 | 内容 |
| --- | --- |
| `plan.md` | 确认要测的业务、预期结果、范围和业务流程图 |
| `report.md` | 业务结果、问题、关键指标和业务简图 |
| `details.md` | 排查问题时需要的详细检查和请求响应记录 |
