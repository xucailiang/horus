# horus 实施记录

以 PRD v0.7、技术方案 v0.4 和 ADR-0003/0004 为正式 M1 边界。
第一条纵向链路同时接入 MCP 与 Skill；此文件记录实际进度，不替代验收证据。

项目接入以 OpenAPI/Swagger URL 为主；源码由宿主 Codex/Claude Code 按需读取。
聊天资料或源码结论随计划的 supportingContext 保存，不建立 Git/源码分析或知识渠道。
内容标识只用于固定审核对象、隔离运行和复现，不引入额外发布版本或迁移层。

## 开工时补齐的约定

- 项目具有与目录位置无关的持久 projectRef。配置、资料、计划、审核为内容寻址
  不可变资产；引用必须在当前项目内解析并重新验证哈希。
- 审核包必须闭包包含 configRef 对应的配置、计划、操作目录/Schema、必要依据与
  审核记录。导入保留逻辑项目身份；目标 origin/base path 变化重新审核，凭据轮换
  不改变审核范围。不得以“绑定 CI 环境”为由改变已批准目标。
- M1 同项目同时只有一个活动运行，其他运行排队，不同项目可以并行。
  运行内可并行独立功能 case，性能 case 独占项目；修复清理也取得项目互斥锁。
- requestId 与参数摘要先持久化；相同请求返回原 runId，不同参数返回冲突。
  Worker 独占认领，已开始的写操作不因工具重试或重连被重发。
- 账本保存 case/step/identity 引用、非敏感资源标识、已审核清理参数及
  intent/confirmed/unknown/cleaned 状态。发送写操作前记录 intent，成功捕获后
  登记 confirmed；崩溃间隙保留 unknown。敏感变量不持久化；修复只允许重新
  执行已批准且在 cleanupAllow 内的 authentication 步骤。无法撤销的旧会话
  或无法确认的资源明确列为残留，不宣称清理成功。
- 数据检查失败率按“至少一条数据断言失败的响应数 / 完成响应数”计算，
  HTTP 错误另算；缺样本、未完成迭代或没有阈值不判性能通过。

## 实施顺序

1. Python 3.12/uv/wheel、共享严格模型、资产完整性与最小 stdio MCP，随包 Skill。
2. OpenAPI/Swagger URL 与接口目录、可选上下文、计划验证及人工审核。
3. reference-api、Hurl、独立 Worker、finally 清理、自动报告和幂等启动。
4. k6 基础并发、阈值及故障矩阵；CLI/CI 已审核包回放。
5. 分支/轮询/身份隔离、workflow-api、双客户端真实 Agent 生成与实际人工确认。
6. 完整静态检查、集成/验收、脱敏与构建、真实客户端断连恢复。

每个检查点都运行相关测试；自动测试中的审核记录不能作为实际人工审核证据。
引擎版本固定 Hurl 8.0.1 / k6 2.3.0；uv 工具版本固定 0.9.11，uv.lock 冻结依赖。

## 当前证据

用户确认项目保持轻量，本阶段不部署 CI；GitHub Actions 已移除，本地验证流程保留。

已有严格模型/内容完整性、stdio MCP、随包 Skill、OpenAPI/Swagger UI URL 导入、
Hurl 功能链路、k6 并发指标及阈值、独立 Worker、启动去重、取消清理和自动报告。
正常/数据错误/延迟及跨项目、审核门槛等场景已有自动测试。基础 wheel 在干净 Python 3.12
环境使用带哈希的冻结依赖完成审核包导入、正常/数据错误回放、退出码和清理验证，未安装 MCP。
取消期间的有界 HTTP 写入先完成捕获；清理不会被普通取消打断。Worker 崩溃后 guardian
停止引擎并在退出前持有项目锁，避免后续运行与孤儿压测重叠。

显式修复清理已接入 MCP/CLI，沿用原审核、项目锁和原 run.id；只恢复非敏感账本变量，
按 cleanupAllow 执行必要鉴权及其鉴权前驱、原 cleanup，不重跑 prepare/exercise 或负载。
中断恢复、禁止重新鉴权、敏感资源 ID 丢失、鉴权断言失败后仍撤销新会话均有回归。
结果不明的旧写入、丢失凭据及未验证清理保留为残留，缺输入跳过不能判通过。

正则断言已接入 HTTP 与 k6，采用 ECMAScript Unicode 语义；模式在送审前校验。
HTTP 匹配复用 guardian/项目锁保护的有界子进程，超时后仍按已捕获 ID 进入 finally。
中文、emoji、空白、反向引用、缺字段及非字符串有回归，并在真实 k6 中核对同一批样例。
已发现固定 k6 运行时对 Unicode 属性转义存在差异；负载计划在送审前明确拒绝此语法，
功能检查仍支持，不把两种引擎的全部语法等价当成已验证结论。

身份配置及 HTTP/负载/清理步骤的 identityRef 已实现；凭据别名引用环境绑定名称。
认证用途的捕获值按用例和身份隔离，始终脱敏且不写入账本值；其他业务数据在用例内共享，
secret 标记控制其脱敏和账本持久化。身份、别名、绑定及变量来源在送审前验证。
新增永久 workflow-api 及独立资料/计划，真实 Hurl/k6 已验证拥有者操作、其他用户读写被拒绝、
越权故障检出、身份切回及独立负载。强杀后分别鉴权、资源清理和新会话撤销已有回归，
丢失的旧会话按身份列为残留；JSON/Markdown/JUnit 均保留执行身份。
有界只读轮询已接入计划、校验和 Worker，操作须同时在 runAllow/pollAllow。
类型化条件支持字面值、先前变量及当前响应的比较和 all/any/not；中间响应只记观测，
直到条件满足才导出捕获并执行最终断言。状态守卫每次检查，网络/协议错误不当作等待。
最大次数计入请求预算，声明的轮询/负载时限合计不得超过运行时限；实际全程仍受总时限约束。
工单正常完成、一直 pending、提交后违规修改及轮询取消后清理已通过真实 HTTP 回归。
条件分支已接入：两条路径提前校验和冻结，预算取最大值；直接使用的输出须在两边均有定义，
路径特有变量通过 requires 或 exists 条件保护。认证输出保留身份，支持嵌套引用。
工单已验证直接完成与等待两种路径，未选步骤及轮询在报告/JUnit 中明确跳过；
强杀恢复仅沿记录的路径重新鉴权，不执行替代鉴权或重复提交任务。
总时限到达后禁止启动后续业务步骤，finally 仍使用独立预算清理；两项审查发现的问题
（超时后的后续写入、未选轮询的报告字段缺失）均保留永久回归。

独立功能 case 现按审核上限 1/2 个执行，同组共享队列，每个 case 使用独立上下文，
清理完成才释放名额；普通检查失败不阻塞独立用例。性能 case 等前组全部清理后独占运行，
后组等性能清理完成再开始。报告保留计划顺序、起止时间及实际功能并行峰值。
取消仅停止活动负载和轮询，在途普通 HTTP 写入继续捕获并清理；未开始用例不发送请求。
真实 Hurl/k6 后端已观察到并行上限、凭据和资源 ID 隔离、性能屏障，以及强杀后双 case
的独立清理；丢失的旧会话仍作为残留保留，排队用例不执行。
全量 147 项测试、Ruff/mypy、Skill 校验、构建及干净基础 wheel 的正常/数据错误、
工单双路径、功能并行回放通过。独立审查未发现可复现的必须修复问题，额外取消探针
确认直接取消调度任务也不会中断两个在途写入及其清理。

报告现保留固定计划中的业务理解、资料引用、覆盖、假设、冲突及未覆盖项，并记录目标。
实际步骤和断言分开索引，避免合法同名引用互相覆盖；中断事件仍映射回原 case，
未执行/未判定检查不计通过。k6 只展示聚合证据，不虚构逐条断言的通过数量。
MCP 分页报告可读取失败请求/响应及负载样本，包含保留数量和每 VU 采样上限；
超长证据明确标注截断，本地 JSON 保留引擎返回的完整有界结果。计划资产损坏时仍产出
错误报告并说明上下文不可核验。运行摘要不重复包含大段业务理解和覆盖表。
报告审查发现的同名引用覆盖和 MCP 失败证据缺失已修复，并各自保留回归；
二次审查及失败鉴权探针通过，分页报告不含运行时凭据、认证对象或 PIN。
