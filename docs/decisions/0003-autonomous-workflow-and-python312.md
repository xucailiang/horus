# ADR-0003：自动测试闭环与 Python 3.12 / uv

日期：2026-10-15。状态：采用。用户同意第一性原理审查后的调整，并明确 Python 统一使用 3.12、工程管理统一使用 uv。

部分替代 [ADR-0002](0002-horus-fastmcp-and-plan-review.md) 的 Python 次版本、仅 CLI 审核及相关流程限制；保留 FastMCP、共享核心、Hurl/k6、不可变计划与人工审核要求。

## 背景

用户目标是：提供已部署后端的地址、文档、源码、凭据和测试边界，自动获得业务理解与测试计划，审核确认后等待报告。仅有通用 HTTP 执行器和一条 CRUD 示例不足以验收该目标。原方案把批准限定到手动 CLI，也增加了不必要的重复操作。

## 决定

1. 开发、测试、CLI/MCP/Worker 与 CI 统一 Python 3.12 系列；.python-version 为 3.12，实施时 requires-python 为 >=3.12,<3.13，类型检查配置为 3.12。uv 管理解释器、环境、依赖、运行和构建，提交 uv.lock，CI 冻结依赖；允许 3.12 系列补丁更新。
2. 自动接入是正式流程：Agent 从资料与用户边界生成接口目录、业务理解、身份/范围建议、请求、链路、数据、捕获和断言。用户不需要先编写逐接口配置或测试脚本；必要资料与能力缺口在送审前集中说明。
3. 业务理解必须能落到可执行测试。M1 明确提供身份隔离、声明式条件分支、有界只读轮询，以及用通用请求/断言表达的状态与跨步骤数据检查。程序拒绝未知动态动作、无限循环、无来源变量和预算超限。
4. CLI 与 Agent 对话是等效人工审核入口。展示具体 reviewBundleRef 后，用户明确确认，由 Agent 调用人工决定记录工具保存 planRef、scopeHash、来源和确认引用；无需再运行 CLI 批准。记录已发生的决定与代替用户作决定严格区分。
5. 对话记录入口采用可信本机/宿主 Agent 模式，校验版本与范围，不宣称仅凭引用/姓名完成了强身份认证。CI 只消费受信的已有审核包，不产生新批准。
6. 审核后自动准备、执行、校验、失败处理、清理并出事实报告。执行有总体时限，清理与报告有独立有界预算。失败、部分阻塞、取消和超时也交付结果；强杀后的后续查询重建中断摘要与账本，不自动重复写入。
7. 报告由核心生成，LLM 解释作为可选追加；CLI 等待完成后直接返回报告引用，Skill 自动等待并呈现。用户不必手动查询 runId 或额外导出才能获得本轮报告。
8. 补测是独立新版本与新运行：当前已批准范围先完成并出报告，补测另行审核。不能借连续补测无限延长原任务或扩大权限。
9. 首条 reference-api 完整链路仍是第一个工程检查点；同一正式 M1 再接入独立 workflow-api，覆盖异步状态、不同身份及非法操作。只替换资料、环境和配置，不修改核心，不单独建设 PoC。

## 验收重点

- 无需用户手写请求、链路、捕获和断言，Agent 真正从两种后端各自的资料生成。
- 当前对话对具体版本的确认可以执行；未确认或版本/范围变化必须阻塞。
- 检出 HTTP 200 数据错误、越权、非法状态变化；有界轮询能成功也能超时失败。
- 审核后正常/异常任务自动收尾并给报告，新增补测不阻塞旧报告。
- 两后端切换无业务特例进入核心；CI 用 Python 3.12 + uv 重放已有批准版本。

## 约束与取舍

首版支持不同业务领域、具备访问与资料条件的 HTTP/REST + JSON 服务。特殊鉴权、缺少身份或无法准备的外部依赖显式报告。预期仍以需求/接口约定/人工补充依据为准，源码帮助推断，不能用当前错误实现反向证明业务正确。两种样例的验收不等于证明任意后端均被完整覆盖。

分支、轮询、身份和第二个后端增加了正式交付工作，但直接用于检验业务理解和自动运行目标；不引入新平台服务或独立 PoC。

实现契约与任务见 [技术方案 v0.3](../TECHNICAL-DESIGN.md)，产品边界见 [PRD v0.6](../PRD-horus.md)。
